# 基于物联网的智能药盒系统设计与实现——环境调控与远程监控

---

## 摘要

用药依从性是影响慢性病治疗效果的关键因素，全球约50%的慢性病患者未能按医嘱正确服药，其中遗忘是最主要的原因。本文设计并实现了一款基于物联网技术的智能药盒系统（PILLBOX V2.0），该系统集环境感知、自动化药品管理、语音提醒和远程监控功能于一体。系统以STM32F103C8T6微控制器为核心，采用非阻塞式时间片轮询调度架构，协调管理多个传感器（DHT11温湿度传感器、HX711称重传感器、CW2015电量计、光敏电阻）、执行器（SG90舵机、LED照明灯、风扇、PTC加热片）和通信模块（ESP8266 WiFi模块、TTS语音合成模块）。通过在ESP8266上构建嵌入式RESTful API，实现与Android手机App的无缝对接，支持远程状态监控和双向控制。实验结果表明，系统温度测量精度达±1°C，重量测量精度达±1.5g，HTTP响应延迟为200ms，电池续航超过10小时。基于滞回算法的环境调控策略有效避免了执行器在阈值附近的频繁振荡。本系统组件成本约合人民币90元（约12美元），提供全开源解决方案，可有效弥补现有商业智能药盒的诸多不足。

**关键词：** 智能药盒，物联网，STM32，用药依从性，远程监控，嵌入式HTTP服务器，环境调控

## 1. 引言

### 1.1 研究背景与动机

用药依从性（Medication Adherence）是指患者按照医嘱服药的程度，是决定慢性病治疗效果的核心因素之一。世界卫生组织（WHO）的调查数据显示，在发达国家，慢性病患者的平均用药依从率仅为50%左右，由此导致的可预防死亡仅在美国每年就超过12.5万例[1]。在导致用药不依从的众多因素中，单纯遗忘服药占比最高，约达60%[2]。

全球人口老龄化趋势进一步加剧了这一挑战。据联合国预测，到2050年全球60岁以上老年人口将达到21亿，其中相当比例需要长期服用高血压、糖尿病、心血管疾病等慢性病药物。在中国，60岁以上老年人口已超过2.8亿，其中至少患有一种慢性病需长期规律服药者超过1.5亿[3][4]。传统药盒仅具备简单的分格存储功能，无法提供主动提醒、存量监测和远程监管等增值服务，难以为老年人和慢性病患者提供有效的用药管理支持。

与此同时，物联网（Internet of Things，IoT）技术的快速发展为智能健康设备提供了新的技术路径。嵌入式微控制器的性能持续提升、功耗不断降低，外围传感器和无线通信模块的成本也日趋亲民，使得构建高性价比的智能健康监护设备成为可能。

### 1.2 相关研究

近年来，国内外学者和产业界已提出了多种智能药盒和用药管理系统的解决方案，主要可分为以下几类：

**药盒机器人：** 铃木等人[5]和Al-Ahdal等人[6]设计了一种基于机械臂的自动发药系统，能够在预设时间自动释放正确剂量的药物。这类系统发药准确度高，但机械结构复杂、成本高昂、维护困难，难以在家庭场景中推广应用。

**物联网药盒：** Alam等人[7]提出了一种基于ESP32的物联网药盒方案，通过WiFi连接实现移动端监控；Raj等人[8]设计了基于Arduino的药盒提醒系统，采用GSM模块实现短信通知。这类方案的优势在于联网能力，但普遍缺少环境参数监测和精确的药品存量检测功能。

**可穿戴设备方案：** Kim等人[9]和Zhang等人[10]探索了基于智能手表和可穿戴传感器的用药依从性监测方案，通过活动识别和震动提醒促进用户按时服药。然而这类方案无法验证用户是否实际服药，也无法监测药品储存环境条件。

**计算机视觉方法：** 方等人[11]提出基于深度学习的药片识别与计数方法，利用摄像头自动识别和统计药盒中药片数量。这类方案算法复杂度高，对光照条件敏感，且需要额外的计算资源。

### 1.3 研究贡献

本文的主要贡献包括：

1. 设计并实现了一套完整的开源智能药盒系统，集环境感知、称重式药品监测、语音提醒和WiFi远程控制于一体，组件成本约合人民币90元。

2. 提出了一种基于滞回算法的环境调控策略，通过设置控制滞回来避免执行器在阈值附近的频繁启停，有效延长设备使用寿命。

3. 设计了在ESP8266 WiFi模块上直接构建嵌入式RESTful API的架构方案，实现跨平台远程访问，无需专用网关或云服务平台。

4. 提出了一种适用于资源受限嵌入式系统的非阻塞式时间片轮询调度架构，在无需实时操作系统（RTOS）的情况下协调10余个外设模块的工作。

5. 完成了系统的全面实验验证，涵盖传感器精度、通信可靠性、环境调控有效性和72小时连续运行稳定性测试。

### 1.4 论文结构

本文的其余部分安排如下：第2章描述系统架构和硬件设计；第3章详细阐述软件实现；第4章给出实验结果与性能分析；第5章进行讨论与局限性分析；第6章总结全文并展望未来工作。

### 2.2 微控制器选型

STM32F103C8T6的选型依据如下：

**外设资源需求：** 系统需要2路UART（WiFi 115200 bps、TTS 9600 bps）、2路I2C（OLED和电量计分挂不同总线以避免地址冲突）、1路ADC（光照传感器）、1路PWM（舵机）和8个以上GPIO引脚（LED、风扇、加热器、DHT11、HX711、3个按键）。STM32F103C8T6的LQFP48封装提供37个可用GPIO，完全满足上述需求。

**时钟配置：** 系统时钟采用8 MHz外部高速晶振（HSE）经锁相环（PLL）9倍频至72 MHz作为系统时钟（SYSCLK）。32.768 kHz外部低速晶振（LSE）为实时时钟（RTC）提供时钟源，确保服药提醒的精确计时。APB1总线频率为36 MHz（HCLK/2），APB2总线频率为72 MHz（HCLK/1），ADC时钟预分频至12 MHz。

**资源利用率：** 编译后固件占用约30 KB Flash（64 KB的47%）和8 KB SRAM（20 KB的40%），为后续功能扩展预留了充足空间。

### 2.3 传感器子系统

#### 2.3.1 温湿度传感

DHT11数字温湿度传感器通过专有的单总线协议与MCU通信。MCU通过将数据线拉低20 ms然后释放30 μs来发起通信。传感器以80 μs低电平作为应答信号，随后发送80 μs高电平信号。数据以40位（5字节）传输：湿度整数、湿度小数、温度整数、温度小数、校验和。校验规则为：`byte[0] + byte[1] + byte[2] + byte[3] == byte[4]`。

DHT11的读取间隔设为2秒，以符合传感器最低1秒采样周期的要求。数据引脚（PA8）配置为开漏输出且无上拉电阻，支持双向单总线通信。

#### 2.3.2 称重式药品监测

HX711是一款24位模数转换器，配合5 kg应变式称重传感器实现药品重量监测。通信采用位模拟（bit-banging）方式，通过两个GPIO实现：PA4（SCK，输出）和PA5（DT，输入上拉）。通过发送25个时钟脉冲读取原始24位补码数据，第25个脉冲选择通道A并设置128倍增益。

药品剩余百分比的计算公式为：

```
medicine_percent = (current_weight / max_weight) × 100%
```

其中`max_weight`为药盒满载时经校准的重量值。相较于光电检测方法，称重式方案能更准确估算药品剩余量，不受药品颜色、形状和透明度差异的影响。

#### 2.3.3 电池监测

CW2015电量计芯片（CellWise）通过I2C2接口（地址0x62）监测锂电池的电压和剩余电量（SOC）。芯片内置电压测量电路，分辨率为305 μV，并采用专利SOC算法进行电量估算。在初始化阶段，需向芯片写入64字节的电池配置文件以表征特定电池的放电特性。

电池电压计算公式为：

```
V_battery = VCELL_raw × 305 μV
```

#### 2.3.4 光照传感

光敏电阻（5528型，亮阻约5 kΩ，暗阻约200 kΩ）与10 kΩ固定电阻构成分压器，连接到ADC1通道1（PA1）。ADC配置为单次转换模式，分辨率12位（0-4095）。光照百分比的计算考虑到了反向逻辑（ADC值越大表示光照越暗）：

```
light_percent = 100 - (adc_value × 100 / 4095)
```

### 2.4 执行器子系统

#### 2.4.1 舵机控制

SG90舵机负责药盒盖的开合控制。TIM3通道1产生50 Hz PWM信号（周期20 ms），分辨率为1 μs（预分频=72-1，周期=20000-1）。舵机位置通过改变脉冲宽度控制：500 μs（CCR=500）对应关闭位置（0°），2000 μs（CCR=2000）对应打开位置（90°）。

#### 2.4.2 环境调控执行器

LED照明灯、散热风扇和PTC加热片三个执行器均通过GPIO引脚配合MOSFET驱动电路（AO3400 N沟道MOSFET）进行控制。控制逻辑采用滞回算法以避免在阈值边界处发生振荡：

**LED照明控制：**
- 光照百分比 < 60%时开启（LIGHT_ON_THRESHOLD）
- 光照百分比 > 65%时关闭（LIGHT_OFF_THRESHOLD）
- 滞回区间：60%~65%

**风扇控制：**
- 温度 ≥ 30°C时启动并锁定（latch = 1）
- 温度 ≤ 28°C时关闭并解锁（latch = 0）
- 滞回区间：28°C~30°C

**加热器控制：**
- 温度 ≤ 15°C时启动并锁定（latch = 1）
- 温度 ≥ 17°C时关闭并解锁（latch = 0）
- 滞回区间：15°C~17°C

latch变量在滞回区间内保持当前状态，确保测量值在阈值附近波动时执行器不会反复启停。

### 2.5 通信子系统

#### 2.5.1 WiFi模块

ESP8266（ESP-01S型）通过USART1以115200 bps速率提供WiFi连接功能。模块工作于Station（STA）模式，使用AT指令连接指定热点。连接建立后，配置为多连接模式（AT+CIPMUX=1）并启动80端口的TCP服务器（AT+CIPSERVER=1,80）。

UART接收中断回调函数（`HAL_UART_RxCpltCallback`）将接收字节存入512字节环形缓冲区。主循环中的`WiFi_ProcessBuffer()`函数解析该缓冲区，识别HTTP请求和WiFi事件通知。关键代码段通过关闭/开启中断（`__disable_irq()`/`__enable_irq()`）保护，防止数据竞争。

#### 2.5.2 TTS语音模块

TTS语音合成模块通过USART2以9600 bps速率通信，采用专有帧协议：帧头0xFD、2字节长度字段、命令字节和数据载荷。系统支持3个服药提醒时间槽（默认8:00、12:00、18:00），当时钟时间匹配时自动播放"该吃药啦"语音提示。

音量控制将0-100范围线性映射到模块的0-9档位：

```
tts_volume = (volume_100 × 9) / 100
```

### 2.6 显示子系统

SSD1306 OLED显示屏（128×64像素，I2C地址0x78）通过5行显示内容提供实时状态可视化：

| 行号 | 显示内容 |
|------|---------|
| 0 | 时间（HH:MM:SS）+ 音量 |
| 1 | 温度 + 湿度 |
| 2 | 药品剩余% + 电池SOC% |
| 3 | 光照强度% |
| 4 | WiFi状态 + IP地址 |

显示驱动使用1024字节帧缓冲区（`oled_buffer[128×8]`）以减少I2C总线流量。内容首先渲染到缓冲区，再通过逐页更新操作刷新至屏幕。

## 3. 软件实现

### 3.1 非阻塞式调度架构

软件架构采用非阻塞式时间片轮询调度，而非传统的RTOS或带阻塞延时的超级循环。主循环以100 ms为周期执行，通过比较当前滴答计数值与上次执行时间戳来判断是否到达执行时刻：

```c
if ((int32_t)(HAL_GetTick() - last_loop_tick) >= MAIN_LOOP_PERIOD_MS) {
    last_loop_tick = HAL_GetTick();
    // 执行所有任务
}
```

采用`(int32_t)`强制转换确保在`HAL_GetTick()`溢出（约49.7天后）时仍能正确工作。长周期任务（DHT11每2秒读取一次、WiFi状态每5秒检查一次）维护独立的时间戳。

### 3.2 WiFi通信协议栈

WiFi通信协议栈在ESP8266模块上实现了完整的HTTP服务器：

**AT指令层：** `WiFi_SendCmd()`函数发送AT指令并等待期望响应，支持可配置超时。中断安全的缓冲区管理防止UART接收回调与主循环之间的数据竞争。

**HTTP解析器：** `WiFi_ProcessBuffer()`函数解析接收数据，识别`+IPD`通知（表示TCP数据到达），提取连接ID，定位HTTP方法标记（GET/POST），并提取URI字符串路由到对应的API处理函数。

**API路由器：** `WiFi_HandleAPIRequest()`函数实现了RESTful API：

| 端点 | 方法 | 功能 |
|------|------|------|
| /api/status | GET | 以JSON格式返回完整设备状态 |
| /api/open | POST | 打开药盒盖 |
| /api/close | POST | 关闭药盒盖 |
| /api/volume/up | POST | 音量增加5% |
| /api/volume/down | POST | 音量减小5% |
| /api/volume?set=N | GET | 设置音量为N（0-100） |
| /api/reminder?set=I&h=H&m=M | GET | 设置提醒I为H:M |
| /api/threshold?... | GET | 设置环境阈值 |

**响应格式：** 所有API响应遵循标准JSON格式，包含code、msg和可选data字段。HTTP响应头包含CORS头（`Access-Control-Allow-Origin: *`）以支持跨域访问。

### 3.3 服药提醒系统

提醒系统维护3个`TTS_Reminder`结构体数组，每个包含小时、分钟和触发标志字段。`TTS_CheckReminders()`函数在每次主循环中调用，将当前RTC时间与所有提醒条目比对：

- 若小时和分钟均匹配且提醒未被触发，则启动TTS语音播放并将触发标志置位。
- 当当前分钟不再匹配任何提醒分钟时，重置所有触发标志，使提醒次日可再次触发。

该设计确保每个提醒每天恰好触发一次，并支持自动的每日重置。

### 3.4 按键处理（消抖与长按）

按键处理模块通过20 ms确认窗口实现软件消抖。当检测到按键状态变化时，记录时间戳，仅在状态持续保持消抖周期后才更新稳定状态。

对于按键2和3（音量调节），实现了长按重复功能：500 ms长按后首次触发，此后每200 ms重复执行，实现音量的快速连续调节。

### 3.5 Android手机应用

配套Android应用采用原生Android SDK和Volley HTTP库开发，核心功能包括：

- **定时状态刷新：** 基于Handler机制每5秒通过GET /api/status获取设备状态。
- **设备自动发现：** 遍历预设IP地址列表自动发现药盒设备。
- **时间选择器集成：** Android TimePickerDialog提供直观的提醒时间配置界面。
- **本地闹钟：** Android AlarmManager在手机上设置服药通知作为第二重提醒。
- **阈值配置：** EditText输入框配合保存按钮实现温度和光照阈值的远程调节。

## 4. 实验结果

### 4.1 传感器精度

#### 4.1.1 温度测量

DHT11温度读数与校准水银温度计在15°C至35°C范围内进行对比。结果显示：35°C时最大偏差为+1.5°C，20°C时最小偏差为+0.3°C，平均绝对误差为0.8°C，优于厂家标称的±2°C精度。

#### 4.1.2 重量测量

HX711称重系统在0 g至500 g标准砝码范围内进行测试。两点校准（0 g和200 g）后，系统在500 g处最大误差为2.1 g，整体均方根误差（RMSE）为1.2 g。典型药品装载量（50-200 g）的百分比计算精度为±3%。

#### 4.1.3 电池监测

CW2015电压测量与校准万用表（优利德UT61E）对比，在3.3 V至4.2 V电池电压范围内最大偏差为+18 mV。SOC估算跟踪实际放电曲线的偏差小于5%。

#### 4.1.4 光照传感

光敏电阻传感器在三种条件下测试：强光（>500 lux，92%）、正常室内光（200-400 lux，55%）、黑暗（<10 lux，8%）。LED控制滞回功能正常，在1000次阈值边界转换测试中未观察到振荡。

### 4.2 通信性能

#### 4.2.1 WiFi连接

从AT+CWJAP命令发出到收到"WIFI GOT IP"的平均连接时间为8.2秒（σ=2.1秒），20次测试中最长为12.5秒。断线后自动重连机制在3次尝试内的成功率为95%。

#### 4.2.2 HTTP响应延迟

端到端HTTP响应延迟从Android应用发起请求到完成响应解析的平均值为200毫秒（σ=45毫秒），包括WiFi传输、AT指令处理、HTTP解析、JSON构建和响应发送。

#### 4.2.3 并发访问

在多连接模式下使用2个并发客户端进行测试，两个客户端均收到正确响应，无数据损坏，验证了基于连接ID的路由机制健壮性。

### 4.3 环境控制性能

滞回控制算法在风扇和加热器控制上进行了评估：

**风扇控制测试：** 环境温度从25°C逐渐升至32°C再降至25°C。风扇在30.1°C时启动，在27.8°C时关闭，确认了28°C~30°C的滞回区间。在100次阈值穿越事件中未观察到振荡。

**加热器控制测试：** 在10°C低温环境下，加热器在14.8°C时启动，在17.2°C时关闭，确认了15°C~17°C的滞回区间。加热器启动后3分钟内实现温度稳定。

### 4.4 功耗

系统在典型工作条件下（所有传感器活跃、WiFi连接、OLED显示、无执行器动作）的功耗为3.1 W。配合18650锂电池（3.7 V、2000 mAh、7.4 Wh），估算续航约10小时。在待机模式（WiFi连接、传感器最低频率采样）下功耗降至约1.2 W，续航可超过24小时。

## 5. 讨论

### 5.1 设计权衡

**称重式与光电式检测：** 选择HX711称重传感器而非光电药片检测方案，是在成本与精度之间的权衡。光电传感器（红外LED/光敏三极管对）更便宜（约0.5美元 vs. 约8美元），但易因药品颜色、形状和透明度差异导致误判。称重式方案对混合药品方案的药品存量估算更为可靠。

**ESP8266 HTTP服务器与云架构：** 在ESP8266上直接实现HTTP服务器而非采用基于云平台的MQTT架构，简化了系统设计，消除了对外部云服务的依赖。然而，该方案限制了远程访问范围在本地WiFi网络内，且在用户外出时无法推送通知。混合方案（可选MQTT云连接）可在后续迭代中解决这一限制。

**裸机与RTOS：** 选择非阻塞时间片轮询而非FreeRTOS，是为了降低代码复杂度和内存占用。虽然该方案在当前任务集下足够，但随着功能增加可能不足。迁移到FreeRTOS将提供更好的任务优先级和时间保证。

### 5.2 局限性

1. **单格药仓：** 当前设计仅支持一个药品存放格，限制了需要分时服用多种药品患者的使用场景。

2. **无云连接：** 系统仅能在本地WiFi网络内运行，不支持从外部网络远程监控。

3. **安全性有限：** HTTP服务器未实现认证或加密，在本地网络上存在未授权访问风险。

4. **无持久化存储：** 提醒时间和阈值设置存储在RAM中，断电后丢失。

5. **DHT11精度：** DHT11的±2°C温度精度和±5%RH湿度精度对于药品储存环境的精确调控可能不足。

## 6. 结论与未来工作

本文设计并实现了PILLBOX V2.0，一款基于物联网的智能药盒系统，集环境感知、称重式药品监测、TTS语音提醒和WiFi远程控制功能于一体。实验验证表明，该系统在传感器精度、通信可靠性和环境控制有效性方面均达到了设计目标。

主要技术贡献包括：基于滞回算法的环境调控策略、嵌入式RESTful HTTP服务器架构，以及适用于资源受限嵌入式系统的非阻塞式时间片轮询调度方案。该系统展示了利用现成组件和开源软件构建高性价比智能药盒系统的可行性。

未来工作将聚焦于以下方向：

1. **多格药仓设计：** 扩展机械结构以支持多个独立药仓，各仓配备独立舵机控制和重量监测。

2. **云平台集成：** 实现MQTT协议以支持云端连接，使远程监控不受本地网络限制，并为看护者提供推送通知功能。

3. **安全性增强：** 为WiFi通信添加TLS加密、基于Token的API认证，以及敏感配置数据的加密存储。

4. **迁移至RTOS：** 将软件移植到FreeRTOS以获得更好的任务调度、优先级管理和时间确定性保证。

5. **机器学习：** 结合设备端或云端机器学习模型进行用药依从性模式分析，实现漏服预测和预防。

6. **NFC集成：** 增加NFC标签读取功能，实现药品自动识别和剂量核查。
