## 1. 系统架构概述

### 1.1 系统总体架构

PILLBOX V2.0 采用以 STM32F103C8T6 为核心控制器的集中式架构，通过多路外设接口实现环境感知、药品管理、人机交互和远程通信四大功能子系统。系统架构分为以下层次：

```
┌─────────────────────────────────────────────────────────────────┐
│                     应用层 (Application Layer)                    │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌───────────────────┐  │
│  │ 服药提醒  │ │ 环境调控  │ │ 药品管理  │ │ 远程监控与控制    │  │
│  └──────────┘ └──────────┘ └──────────┘ └───────────────────┘  │
├─────────────────────────────────────────────────────────────────┤
│                     中间件层 (Middleware Layer)                    │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌───────────────────┐  │
│  │ TTS语音  │ │ 执行器   │ │ WiFi通信  │ │ OLED显示驱动     │  │
│  └──────────┘ └──────────┘ └──────────┘ └───────────────────┘  │
├─────────────────────────────────────────────────────────────────┤
│                     驱动层 (Driver Layer)                         │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐    │
│  │GPIO│ │I2C │ │ADC │ │UART│ │TIM │ │RTC │ │SPI │ │DMA │    │
│  └────┘ └────┘ └────┘ └────┘ └────┘ └────┘ └────┘ └────┘    │
├─────────────────────────────────────────────────────────────────┤
│                     硬件抽象层 (HAL)                               │
│                    STM32F1xx HAL Driver                           │
├─────────────────────────────────────────────────────────────────┤
│                     硬件层 (Hardware Layer)                        │
│              STM32F103C8T6 + 外围传感器 + 执行器                   │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 核心控制器选型与设计

### 2.1 MCU选型论证

**选型型号：STM32F103C8T6**

| 参数 | 规格 | 设计需求匹配 |
|------|------|-------------|
| 内核 | ARM Cortex-M3 | 满足实时控制需求 |
| 主频 | 72 MHz | 足够运行多任务调度 |
| Flash | 64 KB | 满足固件存储（编译后约30KB） |
| SRAM | 20 KB | 满足缓冲区和变量存储 |
| 封装 | LQFP48 | 体积适中，引脚数满足需求 |
| GPIO | 37个可用 | 覆盖所有外设接口 |
| USART | 3个 | USART1(WiFi) + USART2(TTS) |
| I2C | 2个 | I2C1(OLED) + I2C2(CW2015) |
| ADC | 2个(10通道) | ADC1_CH1(光照) |
| TIM | 4个 | TIM3_CH1(舵机PWM) |
| RTC | 1个 | 服药提醒时间基准 |
| 价格 | 约 ¥8-12 | 成本可控 |

**选型理由：**

1. **引脚资源充足**：项目需要2路UART、2路I2C、1路ADC、1路PWM、8路GPIO，STM32F103C8T6的LQFP48封装提供37个可用GPIO，完全满足需求
2. **双I2C总线**：OLED和CW2015分别挂载在I2C1和I2C2上，避免总线冲突
3. **双UART**：USART1(115200bps)用于ESP8266高速通信，USART2(9600bps)用于TTS模块
4. **内置RTC**：无需外挂RTC芯片，通过LSE(32.768kHz)提供精确时间基准
5. **生态完善**：STM32CubeMX + HAL库 + Keil MDK开发链成熟稳定

### 2.2 时钟系统设计

```
                    ┌──────────────┐
  HSE (8MHz) ──────►│ PLL          │──────► SYSCLK = 72MHz
  外部晶振           │ ×9 倍频     │        ├─► HCLK = 72MHz (AHB)
                    └──────────────┘        ├─► PCLK1 = 36MHz (APB1)
                                            │   └─► APB1 Timer = 72MHz
  LSE (32.768kHz) ────────────────────────►│
  外部晶振           RTC时钟源              ├─► PCLK2 = 72MHz (APB2)
                                            │   └─► ADC时钟 = 12MHz (PCLK2/6)
                                            └─► RTC = 32.768kHz
```

**时钟配置参数：**

| 时钟域 | 频率 | 来源 | 用途 |
|--------|------|------|------|
| SYSCLK | 72 MHz | HSE×PLL(×9) | 系统主时钟 |
| HCLK | 72 MHz | SYSCLK/1 | AHB总线 |
| PCLK1 | 36 MHz | HCLK/2 | APB1外设(USART2, I2C, TIM) |
| PCLK2 | 72 MHz | HCLK/1 | APB2外设(USART1, ADC, GPIO) |
| ADC_CLK | 12 MHz | PCLK2/6 | ADC转换时钟 |
| RTC_CLK | 32.768 kHz | LSE | 实时时钟 |

**PWM时钟计算（舵机）：**

TIM3挂载在APB1总线上，定时器时钟为72MHz：
- 预分频值 PSC = 72-1 → 计数频率 = 72MHz/72 = 1MHz (1μs分辨率)
- 自动重载值 ARR = 20000-1 → PWM周期 = 20000×1μs = 20ms (50Hz)
- 舵机打开：CCR = 2000 → 脉宽2ms
- 舵机关闭：CCR = 500 → 脉宽0.5ms

| 停止位 | 1 bit |

| RX引脚 | PA3 |

**通信协议：** 帧协议格式

```
帧结构：[FD] [长度H] [长度L] [命令字] [参数] [数据]
  - 帧头: 0xFD
  - 数据长度: 2字节(大端序)，= 数据长度 + 2
  - 命令字: 0x01(播放), 0x02(停止), 0x03(暂停), 0x04(恢复)
  - 参数: 0x00(UTF-8编码)

音量控制帧：[FD] [00] [06] [01] [01] [5B] [76] [30+vol] [5D]
  - vol范围: 0-9
  - 映射: 0-100 → 0-9 (线性映射)
```

## 4. 传感器子系统设计

### 4.1 DHT11温湿度传感器

**接口规格：**

| 参数 | 规格 |
|------|------|
| 供电电压 | 3.3V-5.5V |
| 温度范围 | 0-50°C (±2°C) |
| 湿度范围 | 20-90%RH (±5%RH) |
| 通信协议 | 单总线 |
| 采样周期 | ≥1秒(本项目2秒) |

**通信时序：**

```
主机启动信号:          DHT11响应信号:
          ┌──┐                     ┌───────┐
DATA ─────┘  └───────────────     ─┘       └─────
     │←20ms→│←30μs→│              │←80μs→│←80μs→│

数据位'0':              数据位'1':
     ┌──┐  ┌────┐           ┌──┐  ┌─────────────┐
DATA─┘  └──┘    └──     DATA─┘  └──┘             └──
     │50μs│26-28μs│           │50μs│   70μs      │
```

**数据格式：** 5字节 = 湿度整数 + 湿度小数 + 温度整数 + 温度小数 + 校验和

**校验规则：** `buf[0] + buf[1] + buf[2] + buf[3] == buf[4]`

### 4.2 HX711称重传感器

**接口规格：**

| 参数 | 规格 |
|------|------|
| 供电电压 | 2.7V-5.5V |
| 有效精度 | 24位 |
| 增益 | 128倍(通道A) |
| 输出速率 | 10Hz/80Hz |
| 通信协议 | 串行接口(位模拟) |

**读取时序：**

```
SCK:  ──┐ ┌─┐ ┌─┐ ┌─     ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌┐ ┌─
       └─┘ └─┘ └─┘       └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └┘ └─
DT:   ──────────────────┐ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │
       (等待DT低电平)    └─...24位数据...──────────────────────────────────────────────────────────────────────────────────────────

第25个SCK脉冲: 选择通道和增益(128 = 通道A)
```

**重量计算公式：**
```
weight = (raw_value - offset) / factor
```
- `offset`: 零点偏移(空载时的原始值)
- `factor`: 校准系数(单位重量对应的原始值变化)

### 4.3 CW2015电池电量计

**初始化流程：**

```
1. 写入 MODE寄存器 = 0x30 (复位)
2. 延时 10ms
3. 写入 MODE寄存器 = 0x00 (正常模式)
4. 延时 50ms
5. 写入 64字节电池配置文件到 CONFIG寄存器
6. 写入 MODE寄存器 = 0x00 (确保配置生效)
7. 延时 50ms
```

### 4.4 光敏电阻传感器

**电路设计：**

```
         VCC (3.3V)
          │
         ┌─┐
         │ │ 光敏电阻 (亮阻~5kΩ, 暗阻~200kΩ)
         │ │
         └─┘
          ├──── PA1 (ADC1_IN1)
         ┌─┐
         │ │ 固定电阻 10kΩ
         │ │
         └─┘
          │
         GND
```

**分压计算：**
```
V_PA1 = VCC × R_fixed / (R_LDR + R_fixed)
ADC_val = V_PA1 × 4095 / 3.3
```

## 5. 执行器子系统设计

### 5.1 SG90舵机控制

**控制方式：** PWM信号控制角度

| 参数 | 值 |
|------|------|
| 工作电压 | 4.8V-6V |
| 堵转转矩 | 1.8kg·cm |
| 运转速度 | 0.1s/60° |
| 死区宽度 | 10μs |
| 控制频率 | 50Hz (20ms周期) |

**控制逻辑：**
- 关闭状态：CCR=500 (0.5ms脉宽) → 舵机0° → 药盒盖闭合
- 打开状态：CCR=2000 (2.0ms脉宽) → 舵机90° → 药盒盖打开
- 自动关闭延时：2000ms (预留参数)

### 5.2 LED照明控制

**控制逻辑：** 基于光照阈值的滞回控制

```
if light_percent < LIGHT_ON_THRESHOLD (60%):
    LED = ON (GPIO_PIN_SET, 低电平有效)
elif light_percent > LIGHT_OFF_THRESHOLD (65%):
    LED = OFF (GPIO_PIN_RESET)
```

**滞回区间：** 60%-65%，防止LED在阈值附近频繁切换

### 5.3 风扇控制

**控制逻辑：** 基于温度阈值的滞回控制

```
if temp >= TEMP_HIGH_THRESHOLD (30°C):
    fan_latch = 1 → FAN = ON
elif temp <= TEMP_HIGH_THRESHOLD - 2 (28°C):
    fan_latch = 0 → FAN = OFF
```

**滞回区间：** 28°C-30°C，防止风扇频繁启停

### 5.4 加热器控制

**控制逻辑：** 基于温度阈值的滞回控制

```
if temp <= TEMP_LOW_THRESHOLD (15°C):
    heater_latch = 1 → HEATER = ON
elif temp >= TEMP_LOW_THRESHOLD + 2 (17°C):
    heater_latch = 0 → HEATER = OFF
```

**滞回区间：** 15°C-17°C

## 7. 设计约束与考虑

### 7.1 资源约束

| 资源 | 使用量 | 总量 | 使用率 |
|------|--------|------|--------|
| Flash | ~30KB | 64KB | 47% |
| SRAM | ~8KB | 20KB | 40% |

| I2C | 2 | 2 | 100% |
| ADC通道 | 1 | 10 | 10% |
| TIM通道 | 1 | 12 | 8% |

### 7.2 实时性约束

| 任务 | 周期 | 优先级 | 说明 |
|------|------|--------|------|
| 主循环 | 100ms | 低 | 非阻塞调度 |
| DHT11读取 | 2000ms | 低 | 传感器限制 |
| WiFi数据接收 | 中断 | 高 | UART中断回调 |
| 按键扫描 | 100ms | 中 | 主循环内 |
| OLED刷新 | 100ms | 低 | 主循环内 |
| WiFi状态检查 | 5000ms | 低 | 主循环内 |

### 7.3 可靠性设计

1. **WiFi重连机制**：最多3次自动重连，避免无限重试
2. **数据校验**：DHT11校验和验证，HX711负值保护
3. **滞回控制**：风扇/加热器/LED均采用滞回区间，防止频繁切换
4. **缓冲区保护**：WiFi接收缓冲区512字节，溢出检测
5. **中断保护**：共享缓冲区访问使用`__disable_irq()`/`__enable_irq()`
6. **看门狗**：预留看门狗接口(未启用)
7. **药品不足提醒**：60秒间隔重复提醒，避免过度打扰

## 9. PCB设计指导

### 9.1 布局原则

1. **分区布局**：MCU区、电源区、射频区(WiFi)、模拟区(ADC)分离
2. **去耦电容**：每个IC的VCC引脚附近放置100nF去耦电容
3. **I2C上拉**：I2C总线上拉电阻(4.7kΩ)靠近主机端
4. **晶振布局**：HSE/LSE晶振尽量靠近MCU引脚，走线短直
5. **ADC输入**：光敏电阻模拟信号走线远离数字信号
6. **WiFi天线区**：ESP8266天线区域下方禁止铺铜

### 9.2 层叠设计（4层板推荐）

| 层 | 功能 |
|------|------|
| Top | 信号走线 + 元件焊盘 |
| Inner1 | GND平面 |
| Inner2 | 电源平面(3.3V/5V分割) |
| Bottom | 辅助信号走线 + 元件焊盘 |
