# PILLBOX V2.0 智能药盒系统设计报告

---

## 一、项目背景

### 1.1 选题来源

随着全球人口老龄化进程加速，慢性病患者数量持续增长。据世界卫生组织统计，全球约有50%的慢性病患者未能按医嘱正确服药，其中遗忘服药是最主要的原因之一。在中国，60岁以上老年人口已超过2.8亿，其中超过1.5亿患有至少一种慢性病，需要长期规律服药。然而，传统药盒仅具备简单的存储功能，无法提供服药提醒、药品存量监测和远程管理等功能，难以满足老年人和慢性病患者的实际需求。

本项目旨在设计并实现一款基于STM32微控制器和物联网技术的智能药盒系统（PILLBOX V2.0），通过集成多种传感器、执行器和无线通信模块，实现服药提醒、药品管理、环境调控和远程监控等功能，帮助用户建立良好的服药习惯，提升用药安全性和便利性。

### 1.2 应用场景

本系统主要面向以下应用场景：

1. **家庭老年护理**：独居老人日常服药管理，子女通过手机App远程了解服药情况
2. **慢性病长期管理**：高血压、糖尿病等慢性病患者需长期定时服药
3. **医院病房管理**：护士站集中监控多个病人的服药状态
4. **康复期用药管理**：术后康复患者需严格按时间表服用多种药物

### 1.3 解决的问题

| 问题 | 现状 | 本系统解决方案 |
|------|------|--------------|
| 遗忘服药 | 依赖记忆或简单闹钟 | TTS语音提醒 + 手机App双重提醒 |
| 药品存量不明 | 需人工查看 | HX711称重传感器实时监测药品余量 |
| 环境不适 | 药品储存环境无法控制 | 温湿度检测 + 自动风扇/加热调控 |
| 远程监管困难 | 无法远程了解服药状态 | WiFi联网 + RESTful API + Android App |
| 夜间取药不便 | 需额外照明 | 光敏传感器自动控制LED照明 |
| 电池状态未知 | 突然断电 | CW2015电量计实时监测电池状态 |

### 2.2 工作原理说明

系统工作原理如下：

**1. 系统初始化阶段：**
上电后，STM32F103C8T6依次初始化所有外设：GPIO、ADC、I2C1/I2C2、RTC、TIM3(PWM)、USART1/USART2。随后初始化各功能模块：OLED显示屏显示启动画面，CW2015电量计加载电池配置，DHT11温湿度传感器进入就绪状态，HX711称重传感器完成零点校准，舵机归位至关闭位置，TTS语音模块设置默认音量(50%)，按键系统初始化消抖参数。最后，ESP8266 WiFi模块以STA模式连接指定AP，获取IP地址后启动TCP服务器监听80端口。

**2. 主循环运行阶段：**
系统采用非阻塞式时间片轮询架构，主循环周期为100ms。每个循环周期内依次执行以下任务：

- **按键扫描**：检测3个按键状态，实现消抖和长按重复功能
- **舵机处理**：维护舵机状态（保留扩展接口）
- **温湿度采集**：每2秒通过DHT11单总线协议读取一次温度和湿度
- **光照检测**：通过ADC1采样光敏电阻电压，计算光照百分比
- **执行器更新**：根据温度、湿度、光照数据，自动控制LED/风扇/加热器（滞回控制）
- **重量检测**：HX711读取药品重量，计算药品剩余百分比
- **电池监测**：CW2015读取电池电压和SOC
- **状态上报**：打包设备状态数据，更新WiFi状态缓存
- **TTS提醒检查**：比对RTC时间与预设提醒时间，触发语音播报
- **WiFi数据处理**：解析ESP8266接收的HTTP请求，执行远程命令
- **WiFi连接维护**：每5秒检查连接状态，必要时自动重连
- **OLED显示更新**：刷新时间、温湿度、药品余量、电池、光照、WiFi状态

**3. 远程控制流程：**
手机App通过HTTP GET/POST请求访问ESP8266的TCP服务器。ESP8266将接收数据通过UART1传递给STM32，主循环中的`WiFi_ProcessBuffer()`函数解析HTTP请求，提取URI和参数，调用对应的API处理函数。处理结果以JSON格式通过HTTP响应返回给手机App。同时，控制命令（开/关药盒、音量调节等）被写入命令缓冲区，由主循环在下一周期执行。

**4. 服药提醒流程：**
系统支持3个独立的服药提醒时间（默认8:00、12:00、18:00），可通过按键或App设置。`TTS_CheckReminders()`函数在每次主循环中比对RTC当前时间与预设提醒时间，当小时和分钟匹配且该提醒未被触发时，通过TTS模块播放"该吃药啦"语音提示，并标记该提醒已触发。当时间离开提醒分钟后，自动重置触发标志，为次日提醒做准备。

## 三、硬件设计

### 3.1 主控制器电路

STM32F103C8T6最小系统包括：

1. **电源电路**：VDD接3.3V，VSS接GND，VDDA/VSSA为ADC独立供电，需接100nF去耦电容
2. **时钟电路**：HSE采用8MHz无源晶振+22pF负载电容；LSE采用32.768kHz晶振+6.8pF负载电容
3. **复位电路**：NRST引脚接10kΩ上拉电阻+100nF电容到地
4. **启动配置**：BOOT0接10kΩ下拉电阻（从Flash启动）
5. **调试接口**：PA13(SWDIO)、PA14(SWCLK)接4针SWD调试座

### 3.2 传感器接口电路

#### 3.2.1 DHT11接口电路

```
VCC (3.3V)
  │
  ├──── DHT11 VCC
  │
 DHT11 DATA ──── PA8 (开漏输出/输入)
  │
  └──── 4.7kΩ 上拉电阻 ──── VCC

DHT11 GND ──── GND
```

#### 3.2.2 HX711接口电路

```
称重传感器 ──── HX711模块
                    │
                    ├── VCC ──── 5V
                    ├── SCK ──── PA4 (推挽输出)
                    ├── DT  ──── PA5 (上拉输入)
                    └── GND ──── GND
```

#### 3.2.3 CW2015接口电路

```
CW2015模块
  ├── VCC ──── 3.3V
  ├── SCL ──── PB10 (I2C2_SCL)
  ├── SDA ──── PB11 (I2C2_SDA)
  ├── CIN ──── 电池正极 (经RC滤波)
  └── GND ──── GND
```

#### 3.2.4 光敏电阻电路

```
VCC (3.3V)
  │
 ┌─┐
 │ │ 光敏电阻 (5528)
 └─┘
  ├──── PA1 (ADC1_IN1)
 ┌─┐
 │ │ 10kΩ 固定电阻
 └─┘
  │
 GND
```

### 3.3 执行器接口电路

#### 3.3.1 舵机驱动电路

```
SG90舵机
  ├── VCC (5V) ──── 5V电源
  ├── SIG  ──── PA6 (TIM3_CH1 PWM)
  └── GND ──── GND

注：舵机供电需与MCU供电隔离，避免电机噪声干扰
```

#### 3.3.2 LED/风扇/加热器驱动电路

```
MCU GPIO (PB1/PA7/PB0) ──── MOSFET栅极 (AO3400)
                              │
                              ├── 源极 ──── GND
                              └── 漏极 ──── 负载(LED/风扇/加热器) ──── VCC(5V)

注：低电平有效控制，GPIO输出高电平时MOSFET截止(负载关闭)
```

### 3.4 通信接口电路

#### 3.4.1 ESP8266接口电路

```
ESP8266 (ESP-01S)
  ├── VCC  ──── 3.3V (需500mA+供电能力)
  ├── GND  ──── GND
  ├── TX   ──── PA10 (USART1_RX)
  ├── RX   ──── PA9  (USART1_TX)
  ├── CH_PD ──── 3.3V (10kΩ上拉)
  └── RST  ──── 3.3V (10kΩ上拉)

注：ESP8266峰值电流可达300mA，需独立3.3V稳压供电
```

#### 3.4.2 TTS语音模块接口电路

```
TTS语音模块 (天问TW-TTS)
  ├── VCC ──── 5V
  ├── GND ──── GND
  ├── TX  ──── PA3 (USART2_RX)
  └── RX  ──── PA2 (USART2_TX)
```

### 3.5 OLED显示接口电路

```
SSD1306 OLED (128×64)
  ├── VCC ──── 3.3V
  ├── GND ──── GND
  ├── SCL ──── PB6 (I2C1_SCL)
  └── SDA ──── PB7 (I2C1_SDA)

I2C总线上拉：SCL/SDA各接4.7kΩ上拉电阻至3.3V
```

#### 4.3.1 主循环调度（非阻塞时间片）

```c
// 核心设计：基于时间差判断的非阻塞调度
// 优势：避免HAL_Delay阻塞，所有任务在主循环中轮询执行
if ((int32_t)(HAL_GetTick() - last_loop_tick) >= MAIN_LOOP_PERIOD_MS)
```

**设计要点：**
- 使用`(int32_t)`强制转换处理HAL_GetTick溢出（约49天后）
- 主循环周期100ms，通过`MAIN_LOOP_PERIOD_MS`宏定义

#### 4.3.2 执行器滞回控制

```c
void Actuator_Update(uint8_t temp, uint8_t hum, uint8_t light_percent)
{
    // LED光照控制 - 滞回区间60%-65%
    if (light_percent < thresholds.light_on) {       // <60%: 开灯
        HAL_GPIO_WritePin(LED_PORT, LED_PIN, GPIO_PIN_SET);
        device_state.led_state = 1;
    }
    else if (light_percent > thresholds.light_off) { // >65%: 关灯
        HAL_GPIO_WritePin(LED_PORT, LED_PIN, GPIO_PIN_RESET);
        device_state.led_state = 0;
    }
    // 60%-65%之间：保持当前状态（滞回区间）

    // 风扇温度控制 - 滞回区间28°C-30°C
    if (temp >= thresholds.temp_high) fan_latch = 1;     // ≥30°C: 锁定开
    else if (temp <= (thresholds.temp_high - 2)) fan_latch = 0; // ≤28°C: 锁定关
    // 28°C-30°C之间：保持latch状态
}
```

**滞回控制原理：** 通过latch变量实现状态锁定，在滞回区间内保持上一状态，避免执行器在阈值附近频繁切换，延长设备寿命。

#### 4.3.3 WiFi HTTP服务器

```c
// HTTP请求解析流程
void WiFi_ProcessBuffer(void)
{
    // 1. 检查缓冲区是否有数据
    // 2. 等待5ms确保数据接收完整
    // 3. 原子操作读取缓冲区索引、添加结束符、清空索引（单次关中断完成，避免竞态）
    // 4. 查找"+IPD,"标识（ESP8266数据接收通知）
    // 5. 解析连接ID
    // 6. 提取HTTP方法(GET/POST)和URI
    // 7. 路由到对应API处理函数
    // 8. 构造JSON响应并通过HTTP返回
    // 9. 检测TCP连接关闭事件（,CLOSED），记录连接状态
}

// API路由示例
static void WiFi_HandleAPIRequest(uint8_t link_id, const char *uri)
{
    if (strcmp(api_uri, "api/status") == 0) {
        // 构造状态JSON响应
        snprintf(api_json_buf, sizeof(api_json_buf),
            "{\"code\":0,\"msg\":\"ok\",\"data\":{...}}");
        WiFi_SendFullHTTPResponse(link_id, api_json_buf);
    }
    else if (strcmp(api_uri, "api/open") == 0) {
        wifi_cmd_buf[0] = 'O';  // 写入命令缓冲区
        wifi_cmd_len = 1;
        WiFi_SendFullHTTPResponse(link_id, "{\"code\":0,...}");
    }
}
```

**设计要点：**
- 命令与响应分离：API请求立即返回HTTP响应，控制命令写入缓冲区由主循环执行
- 中断安全：共享缓冲区访问使用`__disable_irq()`保护，缓冲区索引读取和清空在同一临界区内完成，避免竞态条件
- CORS支持：HTTP响应头包含`Access-Control-Allow-Origin: *`
- Keep-Alive连接：HTTP响应使用`Connection: keep-alive`，复用TCP连接，减少重连开销
- 数据完整性：检测到缓冲区数据后等待5ms确保完整+IPD消息接收完毕
- 连接状态追踪：检测ESP8266的`,CLOSED`事件，记录TCP连接关闭状态

#### 4.3.5 按键处理（消抖+长按重复）

```c
void Key_Process(void)
{
    for (i = 0; i < 3; i++) {
        uint8_t cur = HAL_GPIO_ReadPin(keys[i].port, keys[i].pin);

        // 消抖：状态变化后等待20ms确认
        if (cur != keys[i].last_state) {
            keys[i].last_tick = HAL_GetTick();
            keys[i].last_state = cur;
        }

        if ((HAL_GetTick() - keys[i].last_tick) >= KEY_DEBOUNCE_MS) {
            if (cur != keys[i].stable_state) {
                keys[i].stable_state = cur;
                if (cur == GPIO_PIN_RESET) {  // 按下
                    Key_OnPress(i);            // 执行按键动作
                    keys[i].long_press_tick = HAL_GetTick();
                }
            }
        }

        // 长按重复（仅按键2和3，音量调节）
        if (keys[i].stable_state == GPIO_PIN_RESET && i != 0) {
            if (!keys[i].long_press_active) {
                if ((HAL_GetTick() - keys[i].long_press_tick) >= KEY_LONG_PRESS_MS)
                    // 首次长按触发
                    keys[i].long_press_active = 1;
                    Key_OnPress(i);
            } else {
                if ((HAL_GetTick() - keys[i].long_press_tick) >= KEY_REPEAT_MS)
                    // 重复触发（每200ms一次）
                    Key_OnPress(i);
            }
        }
    }
}
```

### 6.2 核心创新点

1. **称重式药品监测**：采用HX711高精度称重传感器替代传统光电检测，可精确计算药品剩余百分比，避免光电检测因药品形状/颜色差异导致的误判

2. **滞回控制算法**：所有执行器（LED/风扇/加热器）均采用滞回区间控制，有效避免阈值附近频繁切换，延长设备使用寿命

3. **嵌入式HTTP服务器**：ESP8266以STA模式运行TCP服务器，实现RESTful API接口，任何支持HTTP的设备均可访问，无需专用网关

4. **双端提醒机制**：MCU端通过TTS语音模块播报提醒，手机端通过AlarmManager推送通知，确保用户不会遗漏服药

5. **模块化软件架构**：各功能模块独立封装（.c/.h），通过hardware_config.h统一配置，便于移植和二次开发

6. **非阻塞调度**：主循环采用时间片轮询，所有任务非阻塞执行，保证系统实时响应
